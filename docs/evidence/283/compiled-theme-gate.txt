Why the gate now reads styled-system/tokens instead of the preset sources.

#284 unioned the two preset files. This replaces that with the compiled theme.
Three conditions, each run against a replayed nightly with the Art Director
fixture stripped of its spacing block — the shape the live agent leaves it in.

1. SCALE IN EITHER PRESET  (today: chassis-preset.ts owns it)
   $ grep -c 'spacing:' elements/preset.ts
   0
   spacing from compiled theme = {1, 2, 3, 4, 5, 6, 7, 8, 9}
   sizes   from compiled theme = {breakpoint-sm .. breakpoint-2xl}
   ok=true  blocking=0  bare-number=0
   $ MOCK_MODE=true node scripts/design-agents.js   -> exit 0, 8 files written

2. SCALE IN NEITHER PRESET  (genuinely gone — the gate must still fire)
   spacing from compiled theme = {}
   ok=false  blocking=44  bare-number=44

3. NO styled-system  (codegen never ran — the gate knows nothing)
   [token-gate] styled-system/tokens not generated — skipping the bare-number check
   readGeneratedTokenScales(...) === null

Case 2 is the one that matters. Reading the compiled theme is not a way of
finding fewer problems; it is a way of finding the real ones. The compiled
`sizes` scale is NOT empty — Panda injects breakpoint-* — and it still carries
no numeric step, which is what keeps `width: '11'` a finding. That was the
11px brand mark, and it is the case the gate exists for.

What the source-parsing approach could not distinguish, and this can:

  empty scale      -> authoritative. Flag.
  unreadable theme -> we know nothing. Skip, and say so.

Conflating those two is exactly how #283 reported 49 findings against correct
code and took the nightly down.

--------------------------------------------------------------------------
2026-09-01 dry run (33510359627) — what it proved and what it exposed
--------------------------------------------------------------------------

PROVED: the #283 fix works. Zero spacing false positives, where the scheduled
run the same morning produced 49. The 44-finding storm did not happen.

EXPOSED: two further defects, both real, neither the agent's fault.

1. width: 'full' -> `width:full`, dropped by the browser.
   Naming any preset in `presets` replaces @pandacss/preset-panda, so this
   theme has had no sizes scale beyond the breakpoint-* keys Panda derives on
   its own. Confirmed against the Panda docs and against
   @pandacss/preset-panda@1.12.0 itself, which defines exactly four keyword
   sizes and no numeric ones.

     before:  sizes = {breakpoint-sm .. breakpoint-2xl}
     after:   sizes = {full, min, max, fit, breakpoint-sm .. breakpoint-2xl}
     numeric sizes keys added: 0
     width: '11' still flagged: yes

2. Attribution named files the engineer cannot write.
   `width:full` was blamed on every file containing the string 'full' —
   `depth: 'full'` in app/content/projects.ts is project metadata, not a style
   prop. With one retry to spend, that message sent it at the wrong files.

   Decoy `depth: 'zzz'` in app/content/projects.ts,
   real `width: 'zzz'` in app/components/Sidebar.tsx:

     before -> app/content/projects.ts, app/components/Sidebar.tsx
     after  -> app/components/Sidebar.tsx

STILL OPEN, not addressed here: the retry budget is exactly one. On the dry
run, pass 1 carried defect A, the retry fixed A and introduced B
(`bg: 'surfaceDeep'`, a colour outside the frozen fifteen), and the run died.
Removing the `width: 'full'` trap removes that particular sequence, but two
unrelated single-token slips are still enough to lose a night. Widening the
budget costs a full engineer regeneration per attempt, so it is a spend
decision rather than a bug fix.
